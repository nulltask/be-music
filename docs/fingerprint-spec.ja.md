# Be-Music Fingerprint 仕様

> ステータス: 草案。このドキュメントの内容はまだ実装されていません。アルゴリズムのバージョン: `bmfp1`。

Be-Music Fingerprint は、譜面をファイルのバイト列ではなく **プレイヤーが遊ぶもの、レーン上に見えるもの** で識別します。次のような違いがあっても、遊んだ内容が同じなら 2 つの譜面ファイルは同じ fingerprint になります。

- 片方に BGA がない、BGM やキー音、メタデータが違う
- エディタ A で保存したものをエディタ B で保存し直した（行の順序、`#WAV` の番号、小節内の分解能、小数の桁数が違う）
- 片方が BMS で、もう片方が bmson

判定、ゲージ、タイミング、ノーツが降ってくる見え方を変えるものが変われば、fingerprint も変わります。

## 1. 2 種類の fingerprint

| 名前                   | 入力                                               | 用途                                                               |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------------ |
| **譜面 fingerprint**   | `#RANDOM` / `#SWITCH` の構造を解決しないままの譜面 | 譜面ファイルの識別（曲リスト、難易度表、スコアデータベース）       |
| **プレイ fingerprint** | 制御構文の分岐をすべて決めた後の譜面               | 1 回のプレイで実際に遊んだ内容の識別（プレイログ、リプレイの照合） |

どちらも同じ正規化ドキュメント（4 章）を使います。制御構文のない譜面は `random` が空なので、譜面 fingerprint とプレイ fingerprint は同じ値になります。

MIRROR / RANDOM / DP フリップなどのレーンオプションは譜面ではなくプレイオプションなので、どちらの fingerprint にも含めません。プレイログでは別に記録します。

## 2. 含めるもの

| 含める（プレイやレーンの見え方に影響する）                                               | 含めない                                                                                                     |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| レーン構成（5 / 7 / 9 / 10 / 14 / 24 / 48 KEY）                                          | タイトル、サブタイトル、アーティスト、ジャンル、`#PLAYLEVEL`、`#DIFFICULTY`、`#COMMENT`、`#TEXT`、`#PREVIEW` |
| 可視ノーツ：位置とレーン                                                                 | ノーツが鳴らす音（キー音の割り当て）                                                                         |
| ロングノーツ：始点、終点、モード（LN / CN / HCN）                                        | BGM（`01` チャンネル）、`#WAV`、`#EXWAV`、`#VOLWAV`、`#WAVCMD`、音量変化チャンネル                           |
| 地雷：位置、レーン、ダメージ                                                             | BGA、レイヤー、POOR 画像、`#BMP`、`#BGA`、`#SWBGA`、`#ARGB`、`#STAGEFILE`、`#BANNER`、`#BACKBMP`、動画       |
| 小節線（小節長）                                                                         | 不可視ノーツ（`3x` / `4x`。判定対象外）                                                                      |
| 初期 BPM、BPM 変化、STOP、`#STP`                                                         | 書き方としての `#LNTYPE`、`#LNOBJ`、`5x` / `6x`（解決後のロングノーツとして含める）                          |
| SCROLL（`SC`）と SPEED（`SP`）                                                           | `#OPTION`、`#CHANGEOPTION`、`#MIDIFILE`、`#PATH_WAV`、`#MATERIALS`、`#BASE`、`#CHARSET`                      |
| `#BASEBPM`（ハイスピードの基準 BPM になり、ノーツの見かけの速さが変わる）                | レーンの中やレーンの上に描かれないもの                                                                       |
| 判定ランク：`#RANK`、`#DEFEXRANK`、bmson の `judge_rank`、`#EXRANKxx` による変化（`A0`） |                                                                                                              |
| `#TOTAL` / bmson の `total`                                                              |                                                                                                              |

## 3. 正規化

fingerprint は **be-music による譜面の解釈** に対して定義します。どのイベントが存在するか（重複オブジェクト、`#LNOBJ`、`#LNTYPE`、bmson の `x` からレーンへの割り当て、レーン構成の判定）はパーサーが決め、この章ではその結果を正規化する方法だけを定めます。

### 3.1 正確な数値

数値はすべて正確な有理数として扱います。ファイル中の小数の文字列（`#xxx02`、`#BPM`、`#BPMxx`、`#STP`、`#TOTAL`、bmson の数値）は、二進浮動小数点数を経由せず、桁の並びから直接有理数にします。IEEE 754 の倍精度値しか手元にない場合は、その値を往復できる最短の十進表記を使います。差は次の寄せで吸収されます。

### 3.2 寄せ

エディタは同じ意図の値を違う桁数で書き（`0.333333`、`0.3333`）、bmson は位置を整数の pulse の格子で持ちます。そこで値を、許容範囲の中で **一番単純な有理数** に寄せます。閉区間の中で分母が最小の有理数を Stern–Brocot 木をたどって求めます。区間の中で一番単純な有理数は一意に決まります。

| 対象                                                                                                                 | 区間                                                                            | 理由                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 小節長（4/4 小節単位）                                                                                               | `[x − ε, x + ε]`、`ε = 1/1920`                                                  | bmson resolution 240（1 小節 960 pulse）の半 pulse。resolution 240 以上の bmson を経由した譜面は元の値に戻る |
| 小節内の位置（その小節の長さに対する割合）                                                                           | `[x − ε, x + ε]`、`ε = 1/1920`                                                  | 同上                                                                                                         |
| 値：BPM、`#BASEBPM`、STOP の長さ、`#STP` の長さ、SCROLL、SPEED、`#EXRANK` の値、地雷のダメージ、`#TOTAL`、判定ランク | `[x(1 − 10⁻⁶), x(1 + 10⁻⁶)]`（`x` が負なら大小を入れ替える。`0` は `0` のまま） | `149.99999999` のような浮動小数点の表記ゆれを吸収する                                                        |

例:

| 入力                          | 寄せた結果                                                             |
| ----------------------------- | ---------------------------------------------------------------------- |
| `0.333333`、`0.3333`、`0.333` | `1/3`                                                                  |
| bmson の 137/960 小節         | `1/7`                                                                  |
| `0.3`                         | `3/10`                                                                 |
| `0.75`、`0.750000`            | `3/4`                                                                  |
| `0.33`                        | `33/100`（`1/3` から遠すぎる。2 桁しか残さないエディタには対応しない） |

この規則から次のことが言えます。

- 許容範囲より小さな違い（120 BPM で 1 小節あたり約 1ms）しかない譜面は、同じ fingerprint になります。
- 1/1920 小節より細かい刻みはまとまることがあります。実際の譜面で使われている例は知られていません。
- 寄せは小節ごと・値ごとに行い、位置は絶対拍に積み上げず（小節, 割合）のまま持つので、長い譜面でも精度の差が蓄積しません。

### 3.3 座標

- **時間** は小節番号と、その小節の中で寄せた位置（`0 ≤ p < 1`）の組で表します。位置がちょうど `1` のものは、次の小節の位置 `0` に移します。
- bmson では小節を `lines` から求めます。小節 `n` は `lines[n].y` から `lines[n+1].y` までで、長さはその幅を `4 × resolution` で割った値です。`lines` がない場合と、最後の line より後ろは、4 拍の小節が続くものとします。
- **レーン** は be-music の割り当てを通した後のプレイ用チャンネル（`11`–`19`、`21`–`29`、24 / 48 KEY の拡張チャンネル）とレーン構成の組で表します。BMS の `16` と、be-music が `16` に割り当てる bmson の `x` は同じレーンです。

### 3.4 イベント

- **ノーツ**: 可視のプレイ用オブジェクトすべて。ロングノーツは終点（小節, 位置）とモードを持ちます。モードはノーツごとに決めます。bmson のノーツごとの `t`、なければ bmson の `info.ln_type`、なければ `#LNMODE`、なければ `1`（LN）です。
- **地雷**: レーン、位置、ダメージ。ダメージは bmson の `damage` があればその値、なければ BMS のオブジェクト値を 36 進数で読んだ値、それが `00` か不正な 2 文字なら `4` です。
- **BPM**: 初期 BPM はヘッダーの値です。`03` チャンネル、`08` チャンネルと `#BPMxx`、bmson の `bpm_events` は、どれも同じ `bpm` イベントになります。
- **STOP**: 拍単位で持ちます。BMS の `#STOPxx` は 4/4 小節の 1/192 単位（拍 = 値 / 48）、bmson の `duration` は pulse 単位（拍 = duration / resolution）です。
- **`#STP`**: `stp` という別のイベントとして、`xxx.yyy` が指す小節と位置に、長さをミリ秒で持ちます。
- **SCROLL / SPEED / EXRANK**: 値を持つ `scroll`、`speed`、`exrank` イベントです。

何も変えないイベントは落とします。

- すでに有効な BPM と同じ値への BPM 変化、長さ `0` の STOP や `#STP`
- すでに有効な値と同じ値への SCROLL や SPEED の変化（どちらも初期値は `1`）
- 直前の `#EXRANK` 変化と同じ値への `#EXRANK` 変化
- 同じ種類の変化が同じ時刻に複数ある場合は、be-music が適用するもの（譜面上で最後のもの）だけを残す

小節線: 小節数は「含めるイベントがある最後の小節 + 1」とし、長さが `1` でない小節だけを列挙します。含めるイベントがある最後の小節より後ろの小節は fingerprint に含めません。

### 3.5 ヘッダーの値と既定値

| フィールド | 規則                                                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `laneMode` | be-music が判定したレーン構成。例: `"7"`、`"14"`、`"9"`、`"24"`                                                                                      |
| `bpm`      | 初期 BPM                                                                                                                                             |
| `baseBpm`  | `#BASEBPM`。なければ `null`                                                                                                                          |
| `judge`    | `#DEFEXRANK`（BMS）または `judge_rank`（bmson。省略時は `100`）があれば `{"exRank": v}`。なければ `#RANK` から `{"rank": n}`。省略時は `2`（NORMAL） |
| `total`    | `#TOTAL` なら `{"bms": v}`、bmson の `total` なら `{"bmson": v}`、譜面が指定していなければ `null`                                                    |

`#RANK` と `exRank` の軸は分けて持ちます。ルールセットごとに読み替えの表が違い、`#RANK 2` と `#DEFEXRANK 100` は一般には置き換えられないためです。BMS の `#TOTAL` と bmson の `total` も分けて持ちます。bmson の `total` は、計算で求めた既定値に対する割合だからです。`#TOTAL` が省略されている場合は、特定のルールセットの既定値に置き換えず `null` のままにします。

### 3.6 制御構文（`#RANDOM` / `#SWITCH`）

プレイ fingerprint では、プレイで使った値で制御構文を解決し、`random` は空になります。

譜面 fingerprint では、制御構文の外にある部分はこれまでどおりトップレベルの各リストに入れ、制御構文のブロックはそれぞれ `random` のノードにします。

- `#RANDOM` は `{"random": max, "branches": [...]}`、`#SWITCH` は `{"switch": max, "branches": [...]}` です。
- 各分岐は `{"when": value, ...}`（`#DEF` / `#ELSE` なら `{"default": true, ...}`）で、トップレベルと同じリスト（`measures`、`notes`、`mines`、`timeline`、入れ子の `random`）を、同じ方法で正規化して持ちます。
- 同じ `#RANDOM` の下で同じ値を持つ兄弟の `#IF` ブロックは、1 つの分岐にまとめます。分岐は値の順に並べ、既定の分岐は最後に置きます。空の分岐は落とします。
- `#SETRANDOM n` と `#RANDOM 1` は結果が 1 通りしかないので、その場で解決します。
- すべての分岐に共通する内容を外に出す（ホイストする）ことはしません。この違いだけがある 2 つの譜面は、譜面 fingerprint は違い、プレイ fingerprint は同じになります。

## 4. 正規化ドキュメント

```json
{
  "v": "bmfp1",
  "laneMode": "7",
  "bpm": "150",
  "baseBpm": null,
  "judge": { "rank": "2" },
  "total": { "bms": "300" },
  "measures": { "count": "64", "lengths": [["12", "3/4"]] },
  "notes": [
    { "m": "1", "p": "0", "lane": "11" },
    { "m": "1", "p": "1/2", "lane": "16", "end": { "m": "2", "p": "0" }, "ln": "2" }
  ],
  "mines": [{ "m": "3", "p": "1/4", "lane": "13", "damage": "10" }],
  "timeline": [
    { "m": "8", "p": "0", "type": "bpm", "v": "400/3" },
    { "m": "9", "p": "0", "type": "stop", "v": "1" },
    { "m": "16", "p": "1/2", "type": "scroll", "v": "1/2" }
  ],
  "random": []
}
```

- 個数や番号も含め、数値はすべて文字列で書きます。整数は `"n"`、それ以外の有理数は既約で分母が正、符号は分子に付けた `"p/q"`（`"-3/4"`）です。浮動小数点表記、指数表記、`+` 記号は使いません。
- `notes` は `(m, p, lane)` の順、`mines` も同様、`timeline` は `(m, p, type, v)` の順（`type` は文字列として比較）、`measures.lengths` は小節の順に並べます。数値のフィールドは文字列ではなく値の大小で並べます。
- 値のないフィールドは省きます（通常ノーツの `end` / `ln` など）。ただし `baseBpm` と `total` は常に書き、`null` になることがあります。
- ドキュメントは JSON Canonicalization Scheme（[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785)）で直列化します。オブジェクトのキーは整列し、空白は入れず、UTF-8 で書きます。

## 5. 出力

```
bmfp1:<正規化 JSON のバイト列の SHA-256（小文字の 16 進）>
```

`bmfp1` という接頭辞はアルゴリズムのバージョンを表します。含めるものや正規化の方法を変えたらバージョンを上げる（`bmfp2`）ので、違うバージョンの fingerprint が偶然一致することはありません。

## 6. 実装メモ

- 関数は `@be-music/chart` に置く予定です（`computeChartFingerprint` / `computePlayFingerprint`）。プレイログにはプレイ fingerprint を記録する予定です。
- 寄せには BMS の値の十進文字列が必要ですが、パーサーは今のところ数値として保存しています。保存されている倍精度値を往復できる最短の十進表記で代用して構いません（3.1 節）。
- テストでは少なくとも次を確かめます。同じ譜面で、行の順序を入れ替えたもの、`#WAV` の番号を振り直したもの、小節内の分解能が違うもの、小数の桁数が違うもの。BMS の譜面と、それを bmson に変換したもの。BGA / BGM / キー音を変えても fingerprint が変わらないこと。含める項目をそれぞれ変えると fingerprint が変わること。
