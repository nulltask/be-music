# 0034: Execute chart-authored M-SUDDEN, the skin-level CRAZY options and the legacy aliases at the playfield level

## Context

[ADR 0032](./0032-chart-authored-visual-families.md) executes HIDDEN, CHANGE-HS and the CRAZY size / X-wave options at program profile version 2 and leaves the rest of nanasigroove's display options diagnosed: `HIDDEN_M-SUDDEN` (a lane cover the player moves with F3–F5), the CRAZY options `STAR`, `SPIN`, `CLONE*`, `S-CLONE`, `LINEMOVE*`, `YWAVE*`, `XYWAVE*`, `3DWAVE*`, `HIDJUDGE`, `DARK*` and `REVERSE`, and the legacy `774:HID-*` / `774:CRA-*` IDs. Issue #931 asks to execute them. The sources describe each in a sentence ([hitkey's catalog](https://hitkey.nekokan.dyndns.info/option.htm): "notes glitter in rainbow colors", "a translucent afterimage appears behind each note", "the judgment line keeps moving up and down", "some screen elements are not displayed", "the note-chart is displayed upside down") and give no period, amplitude, colour, layout or list of elements. The owner decided that an option the chart sets wins over the player's own setting for the same item.

Several of these options restyle parts that Be-Music's four browser families and the terminal draw differently. An LR2 or beatoraja skin authors its own judgement line, lane background, judge display and bombs; the shared renderer controls only the note stream, the lane covers and LIFT, the BGA layer and which judgments and bombs it hands the skin.

## Decision

**Program profile version 3.** `CHART_OPTION_PROGRAM_VERSION` becomes 3. `hidden` gains `M-SUDDEN`; the CRAZY wave subfamily gains `YWAVE`, `YWAVE2`, `XYWAVE`, `XYWAVE2`, `3DWAVE` and `3DWAVE2`; and the states gain seven exclusive CRAZY fields: `crazyColor` (`STAR`), `crazySpin` (`SPIN`), `crazyClone` (`CLONE`, `CLONE2`, `S-CLONE`), `crazyLine` (`LINEMOVE`, `LINEMOVE2`), `crazyJudge` (`HIDJUDGE`), `crazyDark` (`DARK`, `DARK2`) and `crazyReverse` (`REVERSE`). `CRAZY_OFF` clears every visual CRAZY field (and, as before, the gameplay CRAZY options of [ADR 0033](./0033-chart-authored-gameplay-options.md)). Replay parsing accepts versions 1, 2 and 3 and rejects a field or a value of a later version than the recording's own, so a version-1 or version-2 replay can never activate a version-3 option.

**Legacy aliases.** The legacy IDs map to their modern IDs from hitkey's catalog (`HID-HIDDEN1` → `HIDDEN_HIDDEN`, `HID-HIDJUDGE` → `CRAZY_HIDJUDGE`, `CRA-NORMAL` → `CRAZY_OFF`, `CRA-ACCEL` → `CHANGE-HS_ACCEL`, `CRA-HARD1` → `CRAZY_GOOD2BAD`, ...; `resolveChartLegacyOptionAlias`). Like the legacy HSP values they are accepted initially only: A6 disregards old IDs, so a timed one is diagnosed `initial-only-alias`. The gameplay aliases (`CRA-HARD1`, `CRA-HARD2`, `CRA-ULTHARD`, `CRA-2JUDGE`) join the initial play options. `CRA-RHS1/2/3` (a playback-rate change), `CRA-HYPER` and `CRA-CPDOUBLE` (they stand for the unsupported `NOTES_DOUBLE` / `NOTES_COPY`) stay `unsupported-option`.

**Formulas.** All are pure, deterministic functions in `@be-music/chart-model` (`resolveChartNoteVisual`, `resolveChartPlayfieldVisual`). `p` is the displayed approach progress after CHANGE-HS (0 on the judgement line, 1 at the lane top), `t` the engine's display chart clock in seconds and `hash(note)` the stable hash of ADR 0032.

| Option                  | Formula                                                                                                                                                                                            |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `YWAVE`, `YWAVE2`       | Displayed progress `p − a · sin(2πnp) / (2πn)`, `n` = 3 / 5, `a` = 0.8 / 1. The slope never goes below 0, so a note stops and goes without moving back; fixed on the line and at the lane top      |
| `XYWAVE`, `XYWAVE2`     | `YWAVE` / `YWAVE2` on the progress plus the `XWAVE` / `XWAVE2` sway                                                                                                                                |
| `3DWAVE`, `3DWAVE2`     | Size multiplier `1 + 0.3 sin(4πp)` / `1 + 0.5 sin(6πp)`, 1 on the line; the source's guessed XY component is left out                                                                              |
| `STAR`                  | A colour multiplied into the note: hue `frac(t / 1.5 + hash(note))` at saturation 0.55 and full value                                                                                              |
| `SPIN`                  | Rotation about the note's centre `2π · frac(t + hash(note))`: one turn per second                                                                                                                  |
| `CLONE`                 | One afterimage `0.08` behind (above) the note at opacity 0.4                                                                                                                                       |
| `CLONE2`                | `CLONE` and one afterimage a lane width to each side at opacity 0.3                                                                                                                                |
| `S-CLONE`               | `CLONE2`, one rising from the line (`1 − p`) and two closing in diagonally (`±1.5p` lane widths), each at opacity 0.25                                                                             |
| `LINEMOVE`, `LINEMOVE2` | The judgement line rises by `A · (1 − cos(2πt / T)) / 2` of the lane on top of the player's LIFT (at most 0.9), `A` = 0.15 / 0.35, `T` = 4 s / 3 s. `CRAZY_OFF` puts it back (unlike nanasigroove) |
| `HIDJUDGE`              | The judge display (verdict, the combo shown with it, FAST / SLOW) is not drawn, as LR2's SILENT automatic judge timing                                                                             |
| `DARK`, `DARK2`         | `DARK` hides the BGA; `DARK2` hides the judgement bombs too                                                                                                                                        |
| `REVERSE`               | The note stream is mirrored about the middle of the lane area: notes rise to a judgement line at the top                                                                                           |
| `M-SUDDEN`              | The player's own SUDDEN+ cover is drawn at its own height while the option holds, switched on or not; F3 lowers it (more covered) and F4 raises it, 1 % of the lane per press (5 % with Shift)     |

STAR, SPIN and CLONE apply to tap notes; a long note keeps its lane geometry (the Y wave moves its head and tail like CHANGE-HS) and a mine keeps its own colour.

**M-SUDDEN.** The cover is the player's own SUDDEN+ (hitkey's catalog notes that M-SUDDEN is LR2's LANE-COVER), so its height lives in the play state and the replay's recorded view, and a replay shows where the player moved it. The chart only forces it to show; it does not change whether the player has the cover switched on, and the F3 / F4 step changes only its height. The step is taken while a course locks the covers, since the chart asked for the cover. F5 stays Be-Music's restart key, so there is no reset key.

**Hosts.** The engine only publishes the state in `PlayerUIFramePayload.chartOptions` (pause holds it, seek looks it up statelessly, an LR2 reversal freezes it); every effect is presentation. Each family applies an effect where the shared renderer controls the part, and documents the rest as a no-op rather than inventing skin semantics:

**Records.** Display-only: they change no notes, judgments, gauge, score, fingerprints or replay inputs; under [ADR 0031](./0031-assist-record-policy.md) they are neither assists nor judge modifiers. M-SUDDEN's cover height goes into the replay's recorded view like any cover change. NONSTOP places these states in each stage's exclusive window as for the version-2 families.

## Consequences

Every display option nanasigroove lists, and the legacy display IDs, now play with a defined, reproducible picture, and older replays keep theirs. The numbers and the element lists (what DARK hides, what HIDJUDGE hides) are Be-Music's; a later change to one would need a new profile version. On LR2 and beatoraja skins REVERSE moves only the note stream, so the skin's judgement line stays at the bottom, and LINEMOVE does nothing on LR2 skins: making these complete would need skin-level support that LR2 and beatoraja skins do not define. Only `NOTES_*`, `GAMELEVEL_*`, `EXTRA_*`, `CRA-RHS*` and the HDX BGAMODE remain diagnosed ([support boundary](../research/chart-authored-options.md#support-boundary-decision)).
