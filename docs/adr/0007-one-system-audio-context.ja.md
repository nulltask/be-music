# システム音は 1 つの AudioContext を共有し、プレイは自分の AudioContext を持つ

Web のプレイヤーでは、プレイ中の譜面の音以外はすべて 1 つの**オーディオサービス**（`@be-music/player-browser/audio` の `createAudioService`）を通ります。最初に使うときに作る 1 つのシステム用 `AudioContext` の上で鳴らします。対象は、選曲 BGM、選曲画面の効果音、決定とリザルトのジングル、譜面のプレビュー、beatoraja スキンの Lua が鳴らす音です。音はバイト列ごとに 1 回だけデコードします。プレイは今までどおり、`interactive` の自分の AudioContext とオーディオバスを、同じサービスから開きます（`openPlayGraph`）。プレイはコンプレッサーを通して毎秒数百のソースを鳴らし、キーを押してから音が出るまでの遅延をできるだけ短くしたいからです。自分の AudioContext を閉じれば、余韻を鳴らしきったあとにすべてのサンプルを一度に止められます。これまで画面は自分の AudioContext を閉じて音を止めていました。共有する AudioContext ではその停止を明示します。各画面は自分を鳴らした音の**オーナー**として渡し、画面を出るときに `stopOwned` を呼びます。

こう決めたのは、画面ごとに AudioContext が 7 つ作られていたからです。

- 標準・LR2 の選曲画面
- リザルトのジングル
- beatoraja の決定とリザルトの BGM
- beatoraja のスキンの音
- beatoraja の選曲画面のプレビュー
- beatoraja の譜面の準備
- プレイごとに 1 つ

Safari は同時に作れる AudioContext が少なく、画面に入るたびに音をデコードし直していました。マスター音量、プレビュー中の BGM の消音、選曲 BGM の音量は何か所にも書かれていて、ずれていました。標準の選曲画面はプレビュー中に BGM を消しますが、beatoraja の選曲画面は消しません。

## 検討した案

- **これまでどおり画面ごとに AudioContext を持つ。** 閉じれば画面が鳴らした音がすべて止まり、管理は要りません。ただし 7 つの AudioContext、繰り返すデコード、画面ごとの配線が残ります。
- **プレイも含めて 1 つの AudioContext にする。** AudioContext の数は最小です。ただしプレイの遅延の設定、バス、後片付けを選曲画面の音と共有することになります。プレイの終わりに `close()` 1 回でグラフ全体を捨てられなくなり、ソースを 1 つずつ止める必要があります。プレイのグラフがノードごとに後片付けできるようになったら見直すかもしれません。
- **画面を出るときに共有の AudioContext を止めるか閉じる。** 次の画面が鳴らし始めた音まで止まります。たとえば、選曲画面を出るときに鳴る決定音です。
