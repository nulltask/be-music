# 0037: バックスピンスクラッチの終点を、記録したスクラッチの回転方向で判定する

ステータス: [ADR 0040](./0040-replay-input-sources.ja.md) が一部を置き換えました。バックスピンスクラッチは記録した入力ソースで判定し、回転方向は表示用にだけ残します。

## 背景

バックスピンスクラッチ（BSS）はスクラッチレーン上のチャージノート（CN / HCN）です。ターンテーブルでは始点で一方向に回し、終点で逆向きに回します。beatoraja はターンテーブルをスクラッチレーンごとに 2 つのキーとして扱い、始点を叩いたのと別のキーが押されたときに終点を判定します（`JudgeManager` の「BSS終端処理」）。スクラッチの離しは、終点の POOR の範囲に入るとき以外は無視します。Be-Music は BSS をほかのチャージノートと同じく離しで判定しており、2 つ目のスクラッチキー（Ctrl、macOS の端末では Option / Alt）はレーンの別名でしかありませんでした（issue #940）。

オーナーは次のように決めました。ロングノートの終点を判定するルールセット（beatoraja の CN / HCN と、名前を言ってはいけないあのゲームのすべてのロングノート）では BSS の終点を逆回転で判定し、LR2 は引き続きすべてのロングノートを LN として演奏する。キーボードは odd-even（スクラッチレーンのキーを交互に 2 方向として扱う）を使う。回転を報告するコントローラーは実際の回転方向を使う。

判定コア、リプレイ、リプレイシミュレーターは、同じ記録入力から同じ判定に至らなければなりません。そのため逆回転は入力として 3 つすべてに届く必要があります。考えられたモデルは 3 つです。

1. **判定側でキーのトークンから方向を導く。** リプレイはすでにトークンを記録していますが、診断用です。ホストによってキーの名前は異なり、タッチレーンはレーンの最初のトークンを送り、コントローラーの方向はそもそもキーではありません。判定側がキー割り当てを知る必要も生じます。
2. **スクラッチレーンを 2 つの入力チャネルに分ける**（beatoraja のモデル）。すべてのレーン対応、ANY KEY の振り分け、リプレイの `channels`、すべてのレーンオプションに、片側ごとに 2 つ目のスクラッチチャネルが必要になります。
3. **押下に方向を記録する。** 入力層が一度だけ方向を決め（コントローラーが報告した回転、またはキーボードの odd-even のキー）、押下が別のフィールドとして持ちます。

## 決定

モデル 3 を採ります。スクラッチの押下は `spin: 'cw' | 'ccw'`（`ScratchSpin`）を持ちます。エンジンの `lane-input` コマンド（コントローラーが設定する）、判定コアの `press` 入力、リプレイの入力イベント（`ReplayInputEvent.spin`、`down` のみ）にあります。キーについては、エンジンが odd-even の規則で回転方向を決めます。`LaneBinding.inputKeys` がスクラッチレーンの物理キーを順に並べ（Shift、次に Ctrl または Option / Alt）、`createScratchSpinByToken` が偶数番目のキーを `'cw'`、奇数番目を `'ccw'` とします。向きのない入力は回転方向を報告しません。タッチレーンは `spin: null` を送り、エンジンがレーンのキーのトークンから回転方向を読まないようにします。非スクラッチキーからの ANY KEY の押下にも回転方向はありません。こうした入力が逆回転を表せるのは BSS を押している間の新たな押下だけなので、`isReverseScratchSpin` は、始点と同じ向きと分かっている押下を除くすべての押下を逆回転とします。回転方向のない押下は BSS を逆回転させ、回転方向のない押下で始点を叩いた後は、以降のどの押下も逆回転になります。

始点を叩いたとき、`isBackSpinScratch(playedMode, scratch)`（ルールセットが演奏するモードがチャージ系で、スクラッチレーン上）であれば、そのロングノートを始点の回転方向とともに BSS として扱います。以降、判定コアとシミュレーターの両方で次のとおりです。

- そのレーンを逆向きに回す押下は、その瞬間にロングスクラッチ終端の窓で終点を判定します（窓の外は POOR、離鍵マージンなし）。
- 同じ向きの押下は押し直しです。
- 離しは何も確定しません。ヘルチャージの BSS のゲージの刻みは、引き続きレーンが押されているかに従います。
- 逆回転しないまま終点の遅れ側の窓が閉じると、終点は見逃し POOR です。

終点の POOR の範囲での離しに対する beatoraja の例外は再現しません。Be-Music のロングノート終端の窓には POOR の範囲がなく、離しは単に無視します。

## 結果

リプレイが回転方向を持つので、リプレイと再シミュレーションは BSS を正確に再現し、後のルールセットの修正でも採点し直せます。この変更より前に記録したリプレイには回転方向がないため、その中で BSS を押している間のどの押下も逆回転になります。フォーマットはまだリビジョン 0 で、古いリプレイのスコアを保つ必要はありません。タッチのプレイヤーは終点でスクラッチをもう一度タップすれば BSS を取れ、ターンテーブルの逆回転より易しくなります。タッチで BSS を取れなくするよりも、それを受け入れます。スクラッチの CN / HCN を含む譜面は beatoraja と名前を言ってはいけないあのゲームで逆回転が必要になり、エンジンのキャラクタリゼーションのフィクスチャと、回帰コーパスのシナリオ（スクラッチのロングノートの終点ごとに逆回転するようになった）のスコアが変わります。ターンテーブルやアナログ軸を持つホストは、押下に `spin` を設定するだけです。コントローラーの入力経路を持つホストはまだありません。キーボードには新しい既定キーは不要です。各スクラッチにはすでに 2 つ目のキーがありました。
