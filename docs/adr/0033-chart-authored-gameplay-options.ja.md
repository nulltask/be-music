# 0033: 譜面指定の RANDOM と判定系 CRAZY はプレイヤーの設定を置き換え、アシストとしない

## 背景

nanasigroove では、譜面の初期 `#OPTION` で `774:RANDOM_*`（MIRROR・RANDOM・RANDOM+・ALL・ALL+）、`774:NOTES_*`、判定に関わる `774:CRAZY_*`（`GOOD2BAD`・`GREAT2BAD`・`HELLJUDGE`・`ADDMINE`）を強制できます。A6 ではいずれも使えません（[調査](../research/chart-authored-options.ja.md)）。[hitkey 氏のカタログ](https://hitkey.nekokan.dyndns.info/option.htm)の説明は一文ずつです。GOOD2BAD は「GOOD・BAD・POOR でゲージが減る」、HELLJUDGE は「本来の判定幅を半分にする（たぶん）」、ADDMINE は「譜面のランダムな位置に地雷を自動で置く」とあります。RANDOM+・ALL+ は特殊ラインも動かし、ALL は左右をまたぎます。アルゴリズム、コースの規則、記録の規則は資料にありません。これらは判定レーンと判定を変えるため、プレイヤー自身のレーンオプション、コースの固定、リプレイ、[アシスト規則](./0031-assist-record-policy.ja.md)が決める記録に関わります。同じ項目では譜面の指定がプレイヤー自身の設定に優先する（譜面作者の演出として）、とオーナーが決めました（#844）。

## 決定

**コンパイル。** `compileChartPlayOptions` は、解決済み譜面の初期宣言から大文字小文字が一致する現行 ID をソース順に読み、同じ系列では後のものが勝ちます。`RANDOM_OFF` は配置を解除します。`CRAZY_OFF` はそれより前に宣言した判定系 CRAZY をすべて解除します。表示系 CRAZY のサブ系列を解除する表示操作でもあり続けます（[ADR 0032](./0032-chart-authored-visual-families.ja.md)）。A6 でも同じです。表示側のコンパイラはこれらの初期宣言を診断しなくなり、A6 での使用は `initial-only-option` と診断します。`NOTES_*` は `unsupported-option` のままです。DOUBLE と COPY はプレイ形式（COPY はシングル譜面をダブルにする）と、すべてのホストが描くレーン配置を変えるため、別の変更とします。

**解釈**（Be-Music の式で、ネイティブとの一致は主張しません）：

| オプション              | Be-Music の効果                                                                                                                                                                                                   |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MIRROR`・`RANDOM`      | 既存の MIRROR・RANDOM を両サイドに適用し、プレイヤーの固定レーンと M-RAN は外す                                                                                                                                   |
| `RANDOM+`               | 既存のスクラッチを含む RANDOM-EX を両サイドに適用（スクラッチのない 9 KEY では通常の RANDOM）                                                                                                                     |
| `ALL`・`ALL+`           | ダブル譜面では両サイドの鍵盤をまとめて 1 回シャッフル（`ALL+` はスクラッチも含む）。シングル譜面では `RANDOM`・`RANDOM+`                                                                                          |
| `GOOD2BAD`・`GREAT2BAD` | GOOD の幅を GREAT の幅にし、GOOD になるはずの打鍵を BAD にする（beatoraja の `NO_GOOD`）。`GREAT2BAD` は GREAT と GOOD を PGREAT の幅にする（`NO_GREAT`）。名前から解釈し、カタログのゲージだけの説明は再現しない |
| `HELLJUDGE`             | すべての判定幅（PGREAT から BAD、ノートとロングノート終端）を半分にし、マイクロ秒単位で丸める。空 POOR の幅は変えない                                                                                             |
| `ADDMINE`               | 既存の ADD_RANDOM 地雷モディファイア。空きセルごとに独立に抽選し、0.9 を超えたら地雷を置く                                                                                                                        |

**優先順位。** 譜面のオプションは、同じ項目のプレイヤーの選択を置き換えます。配置は両サイドのレーンオプションを、ADDMINE は地雷オプションを置き換えます。コースのレーン固定（`grade`・`grade_mirror`）でも譜面は抑止しません。Leaderboard のコース検査は、譜面が配置を強制したステージを受け入れます。判定変更は、HELLJUDGE で幅を半分にした後、コースの `no_good`・`no_great` 制約と合成し、より厳しい方が勝ちます。NONSTOP では適用しません。つないだ 1 回のプレイは 1 つの ruleset と 1 つの配置で動くため、各ステージの宣言をステージ付きの `unsupported-option` として診断します。

**実行する場所。** 判定変更は `resolveRuleset`（`chartJudge`）の一部で、ライブの engine とリプレイシミュレーターが共有します。サーバーの再シミュレーションでも再現されます。ブラウザのホストは譜面を準備するときに配置と ADDMINE を適用し（`applyChartPlayOptions`）、ノートを engine に渡します。ターミナルにはレーン・地雷オプションがないため、判定変更だけを適用します。

**リプレイ。** 譜面が何かを強制したとき、`chart.chartPlayOptions` に `{ version: 1, options }` を記録します。配置と地雷の結果はすでに `chart.notes` にあります。シミュレーターは記録した判定変更を適用し、ソースを再コンパイルしません。このフィールドのない、この変更より前のリプレイは元の判定を保ちます。リプレイ再生では記録したプログラムを渡し、古いリプレイには空のプログラムを渡します。`play.randomLane` と `play.mineModifier` には、プレイヤーの値の代わりに、実際に使った譜面の値を記録します。

**記録。** これらは譜面に由来し、出典の nanasigroove にはアシストの区分がありません。譜面をプレイする全員に適用されるため、プレイヤーを分けません。アシストなしと区分します。譜面が配置を強制したプレイでは、アシスト規則がレーンの値を見ません（RANDOM-EX と記録した譜面の RANDOM+ は beatoraja の LIGHT ASSIST ではありません）。判定変更と ADDMINE も判定結果を加えません。プレイヤー自身のアシストは従来どおり数えます。

## 結果

これらを強制する譜面は、作者の演出どおりに遊べ、リプレイでもサーバーでも決定的に再現されます。そのような譜面のランプとランキングは、同じ強制オプションの下でのプレイ同士を比べます。制限が 2 つ残ります。譜面を読めない Leaderboard は記録したプログラムを信頼するため、ログからの削除や追加を検出できません。また `NOTES_*`、NONSTOP での適用、ターミナルでの配置は未実装です。
