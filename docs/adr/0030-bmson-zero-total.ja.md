# 0030: bmson の TOTAL 0 を明示的なプレイ設定で扱う

## 背景

bmson 1.0.0 仕様では `info.total: 0` はライフバーが増えないことを意味する。一方、beatoraja は既定 TOTAL に置き換える。HARD・段位ゲージには TOTAL と独立した回復があるため、実効 TOTAL を 0 にするだけでは仕様を満たさない。[調査](../research/bmson-zero-total.ja.md)に一次資料と元コーパスの結果を残す。0 の使用は bmson 0/28 ファイル、全体 0/2,748 譜面だった。

既定動作を変えると旧 replay の解釈が変わり、異なるゲージ規則の記録が混ざる。ダメージ式・ステージ間の引継ぎ・ランキングの扱いは bmson 仕様の範囲外である。

## 決定

プレイ設定に `bmsonTotalMode: 'beatoraja' | 'spec'` を追加する。既定は `beatoraja` のままとする。Browser の Play options に **bmson TOTAL 0**、Terminal に `--bmson-total-mode spec` を用意する。すべての判定ルールセット・スキンファミリーに適用し、譜面内容と chart/play fingerprint は変えない。

| 正規化後の入力                 | 互換モード       | 仕様モード      |
| ------------------------------ | ---------------- | --------------- |
| 百分率 TOTAL 0                 | 従来の既定回復   | 正の回復を停止  |
| 正の百分率 TOTAL               | 従来の百分率計算 | 同じ            |
| BMS の絶対 TOTAL 0             | 従来の既定値     | 同じ            |
| PRACTICE の明示的な TOTAL 置換 | PRACTICE の規則  | PRACTICE の規則 |

パーサは欠落 TOTAL を 100 に補い、負の native bmson 値を絶対値にする。仕様モードの直接 ruleset facts と型付き replay は正規化済みの非負百分率を必要とし、不正な負の百分率を拒否する。旧 replay の読込と互換モードは従来の動作を維持する。

段位・PRACTICE を含め、最終的な主ゲージ・フォールバック・並行ゲージの構築後に回復停止を適用する。正の判定差分を 0 にし、`GaugeSpec.recoveryDisabled` を設定する。`RulesetGauge` は正の raw 差分と倍率適用後の正の差分も抑制する。負の判定差分・HCN を離したときのダメージ・地雷・guts・下限・ボーダー・途中落ちは従来の規則を保つ。ダメージ計算と診断用の実効 TOTAL は互換既定値を使う。このダメージ方針は Be-Music の判断であり、native 互換を主張するものではない。

コースの引継ぎ HP と PRACTICE 開始 HP は初期条件として維持する。PRACTICE で TOTAL を明示した場合は 0 を含めて元譜面の方針を置き換え、既存の PRACTICE 計算を使う。明示しない場合は元譜面の百分率 0 で回復を止める。ノート数 0 でも有限値を保ち、既存のクリア・落ち判定を使う。段階式コースは各ステージで解決する。結合 NONSTOP は選択済みの 1 つの TOTAL と明示単位を使い、ステージごとの 0 遷移を導入しない。

## replay と記録

省略可能な型付き `play.bmsonTotalMode` を記録し、列挙値を検証する。シミュレータと Browser の replay 再生は記録値を使う。省略時は再生側の選択にかかわらず `beatoraja` とし、汎用の `play.options` は型付き判定値を上書きしない。

影響を受ける手動プレイも演奏・replay 再生に対応する。送信結果は `unranked: 'bmson-total'` として保存・シミュレーションし、通常のランキング・自己ベスト・ローカルベストに反映しない。影響を受ける実施済みステージがあるコース、および選択 TOTAL が該当する NONSTOP も同様とする。正の TOTAL で仕様モードを選ぶだけなら動作は変わらず、比較対象に残る。複数条件に当てはまる場合、既存のテンポ・単独ステージ・未公開コースの理由を優先する。DB の理由列は制約のない nullable text なので、アプリの列挙値拡張にデータ移行は必要ない。

replay ダウンロードは利用できる。replay スロットの自動保存は記録を保持できるプレイだけという既存の条件を維持する。将来比較区分を追加しても chart fingerprint の変更は不要である。

## 検証

正規化前後の入力・全ゲージファミリー・固定回復・HCN 倍率・地雷と raw 差分・フォールバックと並行ゲージ・引継ぎ・PRACTICE 優先順位・ノート数 0・型付き replay 検証・旧既定値・実プレイとシミュレーションの一致・ローカル記録・サーバの保存のみの応答を確認する。元コーパスに該当譜面がないため、TOTAL 0 は自作 fixture で検証する。元 bmson 28 ファイルはハッシュを照合し、元ファイルを変更せず互換・仕様モードを比較する。
