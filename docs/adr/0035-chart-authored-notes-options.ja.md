# 0035: 譜面指定の NOTES オプションはエンジンで譜面を変換し、フィンガープリントがゲームプレイオプションを持つ

## 背景

[ADR 0033](./0033-chart-authored-gameplay-options.ja.md) は `774:NOTES_*` を診断のまま残しました。DOUBLE と COPY はすべてのホストが描くレーンを変え、COPY はシングルプレイの譜面をダブルプレイにします（#932）。記述は [hitkey 氏のカタログ](https://hitkey.nekokan.dyndns.info/option.htm) だけです。DOUBLE は「特殊ライン以外のノーツを倍にする」（特殊ラインはターンテーブルとフットペダル）。COPY はシングルプレイの譜面を特殊ラインを除いて左右反転し、2P 側に写します（DBM）。5 KEY の `[11..15, 16]` は 2P が `[15..11, 16]` の 10 KEY に、9 KEY は 18 KEY になります。10・14・18 KEY と OCT/FP では「何も起きない」。DBLCOPY は DOUBLE と COPY の組み合わせです。`NOTES_OFF` で解除でき、`CRAZY_OFF` では解除されません。いずれも初期指定のみで、旧 ID は `CRA-HYPER` / `CRA-CPDOUBLE` です。DOUBLE の配置規則、コースの規則、記録の規則は書かれていません。

キーモードの変化は、ホストが描くスキン、記録（譜面ごと）、コース（1 コース 1 キーモード）、リプレイに及びます。また Leaderboard は譜面そのものを受け取らず Be-Music Fingerprint の文書だけを受け取り、その文書は `#OPTION` を除いていたため、`chart.chartPlayOptions` を検証できませんでした。

## 決定

**コンパイル。** `compileChartPlayOptions` は大文字小文字が一致する新 ID から `notes: 'DOUBLE' | 'COPY' | 'DBLCOPY'` を加えます。`NOTES_OFF` で消え、`CRAZY_OFF` では残ります。旧 ID は他の系統と同じく診断のままです。記録するプログラムは `version: 1` のままです。以前の記録側は `notes` を書かず、以前の厳密なパーサーはこれを拒否するため、解釈が変わるリプレイはありません。

**解釈**（Be-Music 独自。本家との一致は主張しません）:

| オプション | Be-Music での効果                                                                                                                                                                                                                                                                                                                                                |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DOUBLE`   | 鍵盤のノーツそれぞれに、同じ側の鏡像レーン（`n` 鍵中 `i` 番を `n + 1 - i` 番へ。9 KEY は 9 鍵全体で反転）に相方を加えます。鏡像レーンのノーツの頭から終端まで（両端を含む）に、ノーツ・ロングノーツ・地雷があれば加えません。奇数鍵の中央の鍵には鏡像レーンがありません。スクラッチ・ホイール・FREE ZONE のノーツは 1 つのままです。相方はキー音を引き継ぎます。 |
| `COPY`     | 5 / 7 KEY の譜面を、鍵盤を左右反転し、スクラッチを 2P スクラッチに置いて 2P 側に写します。地雷と不可視オブジェクトも写します。10 / 14 KEY として遊びます。他の配置では何もしません（Be-Music に 18 KEY モードはなく、24 KEY はカタログにありません）。                                                                                                           |
| `DBLCOPY`  | DOUBLE の後、倍にした側を COPY します。COPY が働かない配置では DOUBLE だけです。                                                                                                                                                                                                                                                                                 |

**実行する場所。** `preparePlaybackChart` が、ノーツと地雷の変更の後にノーツを変換します。相方は追加した地雷を避け、ADDMINE の地雷も写ります。変換はバトル変換とホストのレーンオプションより前です。プレイの配置はここで変わるため、どのホストもダブルプレイの配置で並べ、キーを割り当て、判定します。スキンは BATTLE の譜面と同じく、その配置に従います。譜面の RANDOM は変換後の譜面にかかります（写した譜面の ALL は左右をまたぎます）。

**優先順位。** 自身を写す譜面がダブルプレイの譜面を決めます。プレイヤーのバトル変換（SP TO DP、D-BATTLE、BATTLE、TWO-PLAYER、COUPLE）は OFF になります。DP FLIP は作者の左右をそのまま残します。DOUBLE はノーツ変換として、プレイヤーのオプションと組み合わさります。

**コース。** コースのキーモードは 1 つなので、コースのステージ（GRADE、EXPERT、NONSTOP）では COPY を外し、DBLCOPY は DOUBLE を残します。効果を失った指定は `unsupported-option` と診断します。そのステージは譜面の記録（ダブルプレイの譜面の記録）を更新しません（`RecordPlayKind.chartCopyLeftOut`）。NONSTOP は従来どおり、ステージのゲームプレイオプションを適用しません。

**実効プログラム。** `resolveEffectiveChartPlayOptions` は、譜面の配置とコースのステージかどうかから、コンパイルしたプログラムをそのプレイで効くものに絞ります。ブラウザ、エンジン自身の譜面準備（ターミナル）、Leaderboard が共有します。リプレイは実効プログラムだけを記録します。結果はノーツに、ダブルプレイのモードは `chart.laneMode` に入っています。再生は記録した `notes` で変換し、BATTLE のリプレイと同じく 2P 側の地雷とロングノーツの配置を 1P 側から作り直します。

**ターミナル。** ホストが譜面を準備しないとき、エンジン自身が譜面の配置と ADDMINE を適用します。そのためターミナルでも譜面の RANDOM・ADDMINE・NOTES が効くようになります。RANDOM の並べ替えは、移動先ごとに一様に引きます。ターミナルにはレーンオプションも記録するシードもありません。

**記録。** 譜面のフリープレイには常に変換がかかるため、譜面の記録のキーモードは 1 つです。他の譜面指定と同じく、変換はアシストではありません（ADR 0031）。譜面をプレイする全員に適用されるためです。

**Leaderboard。** フィンガープリントの文書は、コンパイルしたゲームプレイオプションをヘッダーの `playOptions` として持ちます（`#RANDOM` の分岐にも入ります）。オプションがなければ省きます。ゲームプレイオプションのない譜面のフィンガープリントは変わりません。ある譜面は、ノーツと判定を変えるため新しいフィンガープリントになります。投稿時、サーバーはプレイ文書（プレイのフィンガープリントで検証済み、L3）から `playOptions` と `laneMode` を読みます。それをプレイの状況に合わせて絞り、`chart.chartPlayOptions` が違うリプレイを `chart-play-options-mismatch`（422）で拒否します。NONSTOP のつなげたプレイは何も記録していなければなりません。

## 結果

NOTES を強制する譜面は、どのホストでも、リプレイでもサーバーでも、倍にした譜面や写した譜面として遊べます。フィンガープリントは、ゲームプレイオプションだけが違う譜面を区別するようになります。`bmfp0` は開発版なので版は上げません。オプションのない譜面のフィンガープリントは変わりません。リプレイが譜面のプログラムを削除や追加すると、プレイのフィンガープリントが変わり、別の譜面を指すことになります。DOUBLE の配置は Be-Music 独自の規則で、nanasigroove と異なる場合があります。選曲画面は COPY の譜面を作者のキーモードで分類したままです。コース中の NOTES COPY の譜面はシングルプレイで遊びます。
