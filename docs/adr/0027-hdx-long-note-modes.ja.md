# 0027: ノート準備前に HDX LONGMODE を解決する

## 背景

保存された charatbeatHDX の公式マニュアルは、`#OPTION charatbeatHDX:LONGMODE 0` を CN、`1` を HCN と定義し、ユーザーの既定値より優先します。HDX は CHANGEOPTION に対応しません。他の方言の `#LNMODE` との関係、重複宣言、大文字小文字の同一視は定義していません。[一次資料の調査](../research/chart-authored-options.ja.md)を参照してください。

Be-Music には CN・HCN の判定がありますが、宣言の保存だけではノート・fingerprint・録画が LN になります。対応を追加する際は、以前の replay と NONSTOP の各ステージのモードも保持する必要があります。

## 決定

RANDOM・SWITCH を選択した後、BMS の譜面モードを、有効な明示的 `#LNMODE`（1・2・3）、最後の有効な初期 HDX LONGMODE、LN の順で解決します。ベンダー名の大文字小文字と引数全体を保持し、空白またはタブで区切った 0・1 だけを受理します。後の不正な宣言は前の有効値を消しません。この優先順位と重複規則は Be-Music の方針であり、ネイティブの方言間動作を示すものではありません。bmson はノート別 `t`、`info.ln_type`、既定値の順を保持し、この BMS 拡張では上書きしません。

未指定モードをユーザーの既定値やコース制約で補完する前に譜面モードを反映します。ユーザーが選択した既存の判定を使い、beatoraja は CN・HCN、LR2 は LN として扱います。命令によるルールセットの変更は行いません。LONGMODE はバージョン1の表示プロファイルに追加しません。時刻付き A6 の LONGMODE は `initial-only-option`、不正な引数は `invalid-parameter` と診断します。

実効ロングノート種別を既存の表現で fingerprint に含め、明示的な LNMODE と一致させます。条件付き LONGMODE ヘッダは LNMODE・レーンオブジェクトと同じ依存関係の因子に含めます。生の表記と表示だけの OPTION は fingerprint の内容を増やしません。BMS 出力は元の宣言を保持し、bmson 変換は実効 `ln_type` を出力します。

replay に記録された譜面モードは、新たに対応した元譜面の宣言より優先します。記録された LN（1）も対象です。以前の配置の再利用でも同じ規則を使います。解決済み譜面を渡した場合も含め、分岐を選んだ後で今回のユーザーの既定値を反映します。

NONSTOP の stitch バージョン3は、BMS ステージに CN・HCN がある場合に bmson のノート別種別を使い、ステージ境界と FIT を通してモードを保持します。バージョン1・2は過去の録画のために以前の BMS 合成動作を保持します。明示的な BMS LNMODE でも起きていた同じ欠落を修正します。既存の bmson コースはノート別の経路を維持します。

## 結果

新しい判定アルゴリズムや描画 family は不要です。実効ノートモードを既存の描画・録画・決定的 replay シミュレーションに渡します。BMS だけの CN・HCN コースも内部では bmson 譜面になる場合があります。ネイティブ BMS は譜面全体の LNMODE しか持たないため、混在モードのコースは bmson で出力して種別を保持します。他の OPTION 系列は #835 で追跡します。
