# 0029: 実行しない bmson フィールドを正規化済みノードに保持する

## 背景

bmson の仕様は未知キーの往復保持を義務付けていません。上流の reader も、オブジェクト型によって無視・拒否の扱いが異なります。そのため保持は Be-Music の編集・交換方針として定義します。[一次資料の調査](../research/bmson-unknown-fields.ja.md)では、公式フィールド、実装済み拡張、共用 decoder 型の未使用フィールドを区別します。元の28ファイルに任意の未知キーはありませんが、GRAYSCALE の4譜面には実行しない hidden note の `damage: 0` が各1件あり、以前の Be-Music は破棄していました。

元の文書を丸ごと保存するだけでは、ノートの移動・削除・並べ替え後に注釈を安全に対応付けられません。ファイル名を識別子にすると、同じ音声を参照する独立したチャンネルも混ざります。不透明なデータによる対応済みフィールドの上書きは、正規化の迂回や意図しない実行につながります。

## 決定

正規化済み bmson ノードに任意の `extraFields: JSONFields` を追加します。ルート・info・BGA のコンテナ／ヘッダ／イベント／シーケンス／フレーム、sound・key・mine のノート、保存用のチャンネル・タイミング項目を対象にします。イベントの注釈は `BeMusicEvent.bmson` に付け、チャンネルの注釈は割り当てた WAV スロットをキーとする `bmson.channelExtraFields` に保持します。`channelKinds` はノートがない場合も元のコンテナ種別を保持します。`lineExtraFields` は正規化済み pulse と小節線注釈を対応付け、native 出力は小節線の resolution 変換時にもラベルを対応付けます。これらのフィールドはレーン推定・ノート・時刻・音声・判定・fingerprint・記録可否に影響しません。

`JSONValue`・`JSONFields` は JSON データだけを表します。公開する `cloneJSONFields` は独立した深いコピーを作り、空または object でない envelope、非有限数、関数、plain object でない値、循環参照を拒否します。不正な envelope はまとまりごと省略します。共有参照も別々にコピーします。JSON の `__proto__`・`constructor` などのキーは、通常の own data property として保持します。IR の再読込は envelope を読み、その名前を再び外部の注釈とは解釈しません。native ソースに文字通り `extraFields` というフィールドがある場合は、envelope の内側で表現できます。

`collectBmsonExtraFields` は外部ノードの型ごとに対応済みキーを予約します。native 出力時は、不正なソース値のため正規化後のフィールドが省略されている場合も含め、注釈から予約キーを除外します。対応済みの正規化値を常に優先します。hidden note の未使用 damage・length・continuation と、mine の未使用 length・continuation は不透明な値として保持し、実行用のイベントフィールドには昇格させません。

Be-Music JSON と `cloneJSON` はすべての envelope を独立して保持します。native bmson 出力は、検証付き保存経路と正規化後の再生成経路の両方で、不透明なキーと正規化値を合成します。注釈の編集も保存データとの同一性判定に含め、古いイベント・チャンネル注釈を復活させずに再生成します。同じファイル名のチャンネルも独立して扱います。ノードを移動・並べ替えすると注釈も追従し、正規化済みノードを削除するとその注釈も削除します。注釈付きの空チャンネルと、未知値だけを持つ BGA コンテナも出力できます。

## 境界

保持対象は有効な正規化済みノードのデータであり、ソースのバイト列ではありません。空白・数値の表記や精度・不正なレコード・正規化で消える重複識別子は保証しません。変更がない保存配列は元の順序を保持できますが、再生成は正規化済み IR に従い、リソース番号や同時刻の発音トリガー順が変わる場合があります。不透明な payload をベンダー固有のリソース参照として解釈・書き換えしません。native BMS 出力に注釈の encoding はなく、新しい譜面の合成も元文書すべてのルート・コンテナメタデータの可逆な結合ではありません。既存の明示的な保存検証スキップ指定は、引き続き保存配列を信頼します。

未知キーから新たな再生動作を推測しません。将来その意味に対応する際は、明示的な parser・model の変更と、対応する replay・fingerprint 方針が必要です。第三者の元譜面・アセットはコミットしません。
