# スキンの種類は描くだけ

各画面の振る舞い（一覧の操作、プレイオプション、譜面の準備、エンジンの設定、入力、終了処理、音）は、実行環境に依存しない**シーンモデル**を扱う、スキンの種類によらない**シーンセッション**に 1 つだけ置きます。標準・LR2・beatoraja の**スキンの種類**は**ファミリービュー**で、モデルを自分のスキンで描き、プレイヤーの操作を**インテント**（フォルダを開く、コースを始める、ゲージを切り替える）に変えて返すだけです。どの画面もライフサイクルは 1 種類（`PixiScene`）で、ホスト向けの API はどの種類も同じです。

こう決めたのは、種類ごとにエンジンのつなぎ方と一覧の実装が 2 つずつ育ち、そのずれがコースの作業で見つかった不具合の大半を生んだからです。コースのあとカーソルが戻らない、PLAY / AUTO がコースバーで効かない、ある種類だけ ESC でエンジンが止まらない、beatoraja で RANDOM / MIRROR が効かない、beatoraja にリプレイと NONSTOP がない、などです。

## 検討した案

- **種類ごとの画面から共通のヘルパーを呼ぶ。** 機能ごとにつなぐ場所が 2〜3 か所残ります。ある種類だけヘルパーを呼んでいない、という今と同じ不具合が起きます。
- **保護されたフックを持つ基底の画面**（標準と LR2 のプレイ画面の作り方）。基底が LR2 固有の概念を抱えたまま 5,900 行に育ち、beatoraja は収まらずに別実装になりました。
