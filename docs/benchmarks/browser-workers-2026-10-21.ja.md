# ブラウザ Worker のベンチマーク — 2026-10-21

複数 Worker により、譜面の一括読み込み・ZIP 展開・WSOLA は高速化しました。一方、単発のプレイ準備と送信準備は、計算量に対してメッセージのコピーと結果の転送が重く、遅くなりました。このマシンでは既定の5 Worker が一括処理に有効ですが、すべての処理が速くなるわけではありません。

## 測定条件

- Apple M5、論理 CPU 10、RAM 32 GiB。macOS arm64、headless Chrome 156.0.8078.48。CPU の速度制限なし。
- 本番用ビルドをローカル配信。Worker 実装は `7a4b7a13`。変更前の読み込みは `f6b7993b` のソースを測定専用 Vite プラグインでそのまま取り込みました。それ以外の比較元は同じ計算を Worker を介さず実行します。
- GdbG BMS Package 2022 の全315譜面、48,422,070バイト。元ファイルは読み取りだけに使い、変更していません。譜面や音声そのものは報告書・リポジトリに保存しません。
- ZIP は同じ譜面を順に4分割して生成し、圧縮後の合計は5,440,529バイトです。入力の読み込みと出力の受け渡しを含む展開のみを測定し、譜面のパースは含めません。
- 音声は、44,000〜256,000バイトの WAV をパス順に並べて均等に選んだ32個、合計18.778秒です。測定前に44.1 kHzへデコードし、WSOLA の速度を0.8にします。同じ音声の全チャンネルはまとめて処理します。デコード時間は含めません。
- 単発の準備には判定対象のノートが最多の `qfeileadh_MESMERA/_MESMERA_07_KOOKY.bms`（4,671ノート、元イベント5,879個）を使用しました。送信準備には同じ実譜面と、そのノートに合わせた合成入力のリプレイを使い、両 fingerprint の検証と JSON の生成・圧縮を行います。アカウント、実際の送信、人のプレイ記録は使いません。
- 各処理・各条件で1回ウォームアップした後、5回測定しました。条件の順番は各周でずらし、計測前に GC を実行します。待機中のページと Worker は維持し、複数条件を同時実行しません。Worker の値にはコピー、キュー待ち、結果の転送、必要なメインスレッドでの再構築を含めます。
- 毎回、結果が比較元と一致すること、実際の Worker がエラーなく完了していることを確認しています。Pixi の描画を含む全体、再生中の入力遅延、ネットワーク時間、最大メモリは測っていません。結果はこのデータセットとマシンでの値です。

## 完了までの時間

単位はミリ秒、5回の中央値です。小さいほど速い値です。[JSON 記録](./browser-workers-2026-10-21.json)に各測定値と出力を残しています。

| 処理                        | 変更前 | 1 Worker | 2 Workers | 4 Workers | 5 Workers |
| --------------------------- | -----: | -------: | --------: | --------: | --------: |
| 譜面の一括読み込み          |  943.8 |   1015.5 |     552.9 |     355.9 |     317.7 |
| ZIP 展開                    |  114.2 |    113.8 |      60.9 |      36.2 |      35.3 |
| WSOLA                       |  126.4 |    201.0 |     104.0 |      68.5 |      52.3 |
| 単発のプレイ準備            |    3.9 |     17.7 |      18.5 |      18.5 |      18.2 |
| Fingerprint・送信データ生成 |   23.5 |     49.0 |      47.8 |      47.1 |      46.6 |

5 Worker では、譜面の読み込みが **2.97倍**、ZIP 展開が **3.24倍**、WSOLA が **2.42倍**になりました。単発の準備は **4.67倍**、送信準備は **1.98倍**の時間がかかっています。後者は順番に行う処理なので、プールを増やすだけでは速くなりません。Worker が1個でも画面との競合は減りますが、ローカル計算より遅くなる場合があります。

## メインスレッドの応答性

10 ms 周期のタイマーについて、各回の最大実行間隔を求めたものの中央値です。通常の間隔は約10 msで、それより短い処理は最初のコールバック前に終わる場合があります。スケジューリングの目安であり、クリックへの応答時間や INP の実測ではありません。

| 処理                        | 変更前 | 1 Worker | 2 Workers | 4 Workers | 5 Workers |
| --------------------------- | -----: | -------: | --------: | --------: | --------: |
| 譜面の一括読み込み          |   69.7 |     11.7 |      12.4 |      12.5 |      13.2 |
| ZIP 展開                    |  114.2 |     11.2 |      11.5 |      11.7 |      11.7 |
| WSOLA                       |  126.4 |     11.3 |      11.1 |      10.8 |      10.6 |
| 単発のプレイ準備            |    3.9 |     11.1 |      10.9 |      10.9 |      10.9 |
| Fingerprint・送信データ生成 |   16.3 |     14.6 |      13.6 |      13.1 |      12.1 |

一括処理では長いタイマー間隔を大幅に減らしています。ローカルの WSOLA では中央値126 msの long task も記録され、Worker 経由では同じ処理で記録されませんでした。ただし、複数の短い処理が連続してタイマーを遅らせる場合があり、long task が0件でも応答性が保証されるわけではありません。[Long Tasks API](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceLongTaskTiming) が記録するのは50 ms以上の個々の処理で、すべてのスケジューリング遅延ではありません。

## 初回のコスト

Worker の起動と初回の計算・JIT を含む最初の譜面読み込みは、変更前958.2 ms、5 Workerで391.4 msでした。これはウォームアップの1回分であり、5回の中央値ではありません。別にプールを作り直して微小な処理を完了させた場合、1・2・4・5 Worker の中央値はそれぞれ6.9・7.1・9.0・9.6 msでした。この起動用の測定には最初の重い計算の JIT が含まれないため、単純に定常状態の値から引いて初回全体のコストを求めることはできません。

## 判断

製品では高速化した譜面読み込み、ZIP 展開、WSOLA の3項目だけを Worker で並列化します。単発のプレイ準備と fingerprint・送信 JSON の生成は、Worker の負担で遅くなったためローカルに戻します。上の測定結果は元の5項目の試作を記録したものです。採用しなかった処理の試作コードは、再測定用のハーネスだけに残します。

## 再実行

```bash
node --conditions=source scripts/bench/browser-workers/prepare.ts "/path/to/GdbG BMS Package 2022"
pnpm exec vp build --config scripts/bench/browser-workers/vite.config.ts
node scripts/bench/browser-workers/run.ts
BENCH_STARTUP_ONLY=1 BENCH_OUTPUT=tmp/bench/browser-workers-startup.json node scripts/bench/browser-workers/run.ts
```

準備処理は `/tmp/be-music-browser-manifest.json` にローカルのマニフェストを作ります。`BENCH_MANIFEST`、`BENCH_OUTPUT`、`BENCH_REPETITIONS` で設定を変えられます。`BENCH_BASE_REF` は比較元の読み込み処理を指定し（既定は `7a4b7a13^`）、ビルド時にも同じ値を指定してください。結果の既定の保存先は `tmp/bench/browser-workers-real.json` です。Chrome のインストールが必要です。ほかの重い処理を止め、比較には同じデータとブラウザを使ってください。
