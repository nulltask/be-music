# n2s 実装仕様

Toy Musical 3 は、ナナシグルーヴ2 の譜面を `.n2s` ファイルに収録しています。Be-Music は ZEXA コンテナを開き、中の譜面を PMS として読み込みます。[ADR 0042](./adr/0042-nanasi-groove-2-charts.ja.md)

## 対応状況

| 操作     | 対応                                                    |
| -------- | ------------------------------------------------------- |
| 読み込み | ブラウザーのライブラリー、端末プレイヤー、Node パーサー |
| 再生     | PMS のレーン配置と BMS 系の再生規則                     |
| 書き出し | 通常の譜面形式。ZEXA の書き出しは未対応                 |

## コンテナ

`@be-music/chart-parser` の `readN2SArchive` はバージョン 1 を読み込み、暗号化の有無に対応します。

| ブロック | 内容                                                     |
| -------- | -------------------------------------------------------- |
| `ZEXA`   | バージョン、フラグ、アーカイブ ID、形式文字列            |
| `DATA`   | ファイルごとの zlib ストリーム                           |
| `INDEX`  | エントリーのフラグ、オフセット、サイズ、Shift_JIS の名前 |

ディレクトリーのエントリーは読み飛ばします。ヘッダーに暗号化フラグがある場合は、名前と展開済みの内容を AES-128-CBC で復号し、記録された平文の長さまで切り詰めます。[n2x 譜面リスト](./n2x-spec.ja.md) も同じコンテナを使います。[互換性の根拠](./format-compat-bms.ja.md#220-ナナシグルーヴ2-の-n2s-コンテナ)・[読み込みの実装](../packages/chart-parser/src/core/n2s.ts)

## 譜面の選択と再生

`parseN2SBytes` はインデックス順にエントリーを読み、最初に見つかった `.pms`、`.bms`、`.bme`、`.bml` を採用します。別の ZEXA コンテナがあれば、その場で内側を調べます。入れ子は外側のコンテナから最大 4 階層までです。コンテナが壊れている場合や譜面が見つからない場合はエラーになります。

取り出したバイト列は `parseBMSBytes` に渡します。文字コードの判別も、得られる譜面データも、中のファイルを単体で読み込んだ場合と同じです。

レーン判定では `.n2s` を `.pms` として扱います。収録された 5 ボタン譜面は、9 ボタン配置の一部を使います。コンテナと取り出した PMS のプレイ用フィンガープリントは一致します。[BMS 実装仕様](./bms-spec.ja.md)
