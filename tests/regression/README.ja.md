# リグレッションコーパス

`corpus.test.ts` は [`examples/test`](../../examples/test/README.ja.md) のすべての譜面をツールチェーン全体に通し、各段階の出力を `__expected__/<譜面名>.json` に固定します。ユニットテストは「関数がどう振る舞うべきか」を検証します。このスイートは「実際の譜面ファイルに対して、ツールチェーンが今どう振る舞っているか」を記録します。そのため、パッケージをまたいでロジックを移すリファクタで、どこかの段階の出力が変わった時点でここが失敗します。

## 各期待値ファイルの内容

- `parse`: メタデータ、リソース、小節、BMS / bmson 拡張、制御構文のディレクティブ、全イベント（`小節:チャンネル@分子/分母=値`）。
- `stringify`: 元の形式に書き戻した譜面（1 行ごとに配列の 1 要素）と `roundTripPlayableNotesEqual`。後者は、出力を再度解析したときに同じ演奏ノーツが得られるかどうかです。
- `variants`: `#RANDOM` の引き方ごとに 1 項目あります（制御構文がある譜面は `random-low` / `random-high`、ない譜面は `default`）。各項目には次の内容が入ります。
  - 引いたパターン、プレイ形態、基準 BPM
  - テンポと STOP の点
  - すべての発音トリガー
  - playlog の譜面情報
  - engine がプレイ用に準備したノーツ列
  - 3 種類の固定入力に対する LR2 / beatoraja / IIDX シミュレータの結果。入力は `missed`（入力なし）、`perfect`（全ノーツをジャストで押す）、`offset`（押すタイミングを全判定窓に散らし、7 ノーツに 1 つは押さない）の 3 つです
  - その隣の `engine` に、同じ入力列を各判定ルールセットで `manualPlay` にリプレイさせたときの engine の結果（と最大コンボ）

時刻は整数のマイクロ秒、拍は 1e-6 に丸めているので、浮動小数点の誤差は差分として出ません。

## 実行と更新

```bash
pnpm test:regression
```

```bash
pnpm test:regression -u
```

期待値ファイルに差分が出ても、それがすぐバグを意味するわけではありません。意図した変更なら `-u` で再生成し、プルリクエストでコードと同じように差分をレビューしてください。`examples/test` に譜面を追加すると、期待値ファイルも自動で追加されます。

## engine のリプレイ

engine はまず各 variant につき入力なしで 1 回動かし、準備したノーツ列を取り出します。入力列はこのノーツ列から作ります。次に、それぞれの入力列を 64 倍速の `manualPlay` で判定ルールセットごとにリプレイします。リプレイは決定的な判定コアを判定の瞬間から次の瞬間へ（記録された各入力のマイクロ秒と、時刻つき判定それぞれの直後のマイクロ秒へ）進める（`advanceJudgeCoreReplay`）ので、結果は tick のタイミングにも再生速度にも左右されず、ほかの段階と同じように固定できます。`engine-determinism.test.ts` はすべての入力列を 1024 倍速でもう一度リプレイし、同じ結果と同じ再記録された入力列になることを確かめます。64 倍速での繰り返し実行は、毎回同じ期待値ファイルと比べるコーパス自身が確かめています。リプレイはほとんどの時間を tick ループの待ちに使うので、譜面は並行して実行します。

engine の結果は、同じ入力列に対するシミュレータの結果の隣に固定します。playlog に記録された engine 自身の結果（`results.native`）とシミュレータの結果が、判定数、FAST / SLOW、EX スコア、判定数の合計、最大コンボ、DJ LEVEL、スコア、最終ゲージ（完全一致）のいずれかの項目で食い違うと、このスイートは失敗します。`packages/player/src/playlog/equivalence.test.ts` は規則ごとに最小のケースで検証し、このスイートは実際の譜面で生じる組み合わせを検出します。

## 差分ファジング

`engine-simulator-fuzz.test.ts` は、すべてのプレイモード（7 / 14 鍵、5 鍵、PMS、24 鍵キーボード）のシード付きランダム譜面で、engine とシミュレータに同じ一致を求めます。譜面は単押し、各 `#LNMODE` のロングノート、地雷、BPM と `#EXRANK` の変化を含み、入力列はすべての判定幅をまたいで・越えて押し、ロングノートを早く・遅く離し、押し直し、地雷の上でキーを押し続けます。各ケースを、抽選したゲージと AUTO SCRATCH の設定ですべての判定ルールセットでリプレイし、食い違う項目があればそのシードとともに失敗します。モードごとに 40 シードを実行します。まれな境界にはもっと多くのケースが要るので、判定を触るときはローカルで数を増やしてください。

```bash
BE_MUSIC_FUZZ_SEEDS=1000 pnpm exec vp test run tests/regression/engine-simulator-fuzz.test.ts
```

失敗したシードはそのまま再現します。修正と一緒に `equivalence.test.ts` へ最小のケースとして落とし込んでください。
