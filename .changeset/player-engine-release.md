Record each input's source, narrow a RANDOM MIX by conditions, and estimate a missing #DIFFICULTY.

- Replays now record the physical input of every press and release (#605): `play.inputSources` lists each source once (`kind` `key` / `button` / `turntable`, a coarse `device` `keyboard` / `controller` / `touch`, a normalised `label`, and a turntable's `direction` `up` / `down`), every `ReplayInputEvent` names one by its required `source`, and `tokens` is gone. `play.analogScratch` optionally names how a host turned an analog turntable axis into presses. `parseReplay` checks unique ids, sources that resolve and turntable directions, and rejects replays recorded before input sources instead of guessing. A source never carries device-identifying data.
- Under beatoraja the scratch rules now follow `JudgeManager`'s `sckey`, in the live judge core and in `simulateReplay` alike: a back-spin scratch ends on a press from another source than the head's (also under That-Which-Must-Not-Be-Named), a release of the head's own source that would judge POOR ends it as a POOR, and a scratch LN is let go only by its head's source. A scratch hold started by a source with no counterpart on its lane (a touch zone, a controller button) plays a lenient rule: any fresh press ends the back-spin scratch. LR2 is unchanged. `ScratchSpin` is now for display only.
- New on `@be-music/player-engine/lanes`: `InputSource` and its `InputSourceKind` / `InputSourceDevice` / `TurntableDirection` types (also on `./signals`), `createInputSourceTable`, `inputSourceKey`, `isSameInputSource`, `keyboardInputSource`, `hasScratchCounterpart`, `endsBackSpinScratch` and `releasesScratchHold`; `isReverseScratchSpin` is removed. New on `./replay`: `parseReplayInputSources`, `parseReplayAnalogScratch` and `UNKNOWN_INPUT_SOURCE`. The `lane-input` and `kitty-state` commands take an optional `source` for controllers and touch, `PlayerOptions.replayInputSources` passes a replay's table with `replayInputs`, and `recordReplay.analogScratch` records the analog algorithm.
- Add the RANDOM MIX conditions and a draw one stage at a time to `@be-music/player-engine/course`: `RandomMixConditions` (including `estimateDifficulty`, which narrows a chart without `#DIFFICULTY` by `RandomMixCandidate.estimatedDifficulty`) with `normalizeRandomMixConditions`, `matchesRandomMixConditions`, `filterRandomMixCandidates`, `listRandomMixKeyModes`, `resolveRandomMixCount`, `isRandomMixKept`, `drawRandomMixStage` (which reads a chart's BPMs only for the charts it walks, with randomness passed in) and `createRandomMixCourse`. `CourseRun` takes `{ endless: true }` for a run without a last stage, to which a host adds stages with `appendStage`.
- Add `estimateDifficultyFromNames`, which reads the `#DIFFICULTY` (1 BEGINNER … 5 INSANE) a chart that names none suggests from its subtitle, the bracketed parts of its title, its bmson chart name and its file name (`[SP ANOTHER]`, `_hyper`, `7a`, `SPH`, `EX2`), `estimateDifficultyFromNoteCount`, beatoraja's note-count fallback (under 250 notes BEGINNER … 2000 and over INSANE), and `resolveDisplayedDifficulty`, which returns the declared value or an estimate with its `basis` (`chart`, `names` or `notes`). Both are exported from `@be-music/player-engine/display`; the rules were tuned on charts that do name their difficulty, where they agree with the declared value 97% of the time (the note count, 60%).
