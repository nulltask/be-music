'@be-music/player-engine': minor

Add LR2's mania chart options and GUIDE SE, follow LR2's HAZARD, lane options and STOP handling more closely, and keep each stage's rules in NONSTOP stitching.

- Add beatoraja's GUIDE SE to the audio session contract: `AudioSession.playGuideSound`, called with the judgment's sound (`resolveGuideSound`, `GUIDE_SOUNDS`) as the engine judges. The `judge-combo` effect says when its POOR takes no note.
- Add LR2's mania option GAMBOL under LR2 rules: `PlayerOptions.lr2Gambol` (1 or 2) fixes the judge windows at VERY HARD, or with GREAT and GOOD narrowed to 12 ms, as the chart opens and at each NONSTOP rank object. Replays record it as `play.lr2Gambol`, and replay simulation applies it.
- LR2's HAZARD (`DEATH`) now needs HP 80 or more at the end of a single chart to clear, as LR2's CheckClear checks it like GROOVE, so a mine can leave a surviving run FAILED. The new gauge pick `DEATH-CORRECTED` is the same gauge clearing by survival; other rulesets read it as their DEATH, and LR2 PRACTICE offers it so players can try the survival clear border. `GaugeSpec` takes an optional `clearBorder`.
- Add LR2's mania chart generators ADD NOTES, LOUDNESS, ADD LONGNOTES and ADD MINES: `PlayerOptions.lr2Mania` holds a rate per generator, and one seed feeds every draw. Replays record `play.lr2Mania` (rates, seed, counts) with the generated chart. ADD NOTES and LOUDNESS are classified `no-save`, ADD LONGNOTES and ADD MINES `light`.
- LR2's nine-key S-RANDOM and CONVERGE can now place a note on the 2P scratch, outside the PMS playfield, as LR2's inclusive draw does (`randomizeSRandomNotes` and `randomizeLR2ConvergeNotes` take an `outside` destination). The corrected `S-RANDOM-CORRECTED` and `CONVERGE-CORRECTED` keep to the nine keys; the corrected CONVERGE is classified like CONVERGE. `randomizeLR2ConvergeNotes` also takes `targetOutside` for LR2's 2P target past the keys.
- Add LR2's mania option SOFTLANDING as the scroll modifiers `SOFTLANDING-1` and `SOFTLANDING-2`: a scroll factor between a half and double is drawn at each measure, and at LEVEL 2 at each note and mine as well. Only the scroll changes; note times and judgment stay as written. Replays record the drawn `play.scrollModifierTimeline` and play it back.
- RANDOM is no longer a source-qualified option: LR2, beatoraja and AC all shuffle the keys once for the whole chart, so it is one bare value, and AC's S-RANDOM resolves to LR2's (`lr2:S-RANDOM`), which places notes the same way. Older values `lr2:RANDOM`, `beatoraja:RANDOM`, `____:RANDOM` and `____:S-RANDOM` still resolve, through the new `canonicalOptionValue`; the new `optionValueSources` names the sources a value belongs to (`lr2:S-RANDOM` is LR2's and AC's).
- Add `resolveNonstopSongInfoState` and `NONSTOP_SONG_INFO_FADE_SECONDS` to `@be-music/player-engine/course`, which tell which stage's song a stitched NONSTOP play shows at a moment and how far its crossfade from the previous stage's has gone. `stitchNonstopCourse` now records each stage's song (`NonstopStitchStage.songInfo`: title, subtitle, artist, genre) for the play screen.
- NONSTOP stitching rule version 4 keeps each stage's own rules, which the stitched chart lost or changed before:
  - A BMS stage in a course stitched as bmson (one with a bmson stage, CN / HCN, or more than 3,843 keys) no longer plays its keysounds polyphonically or draws its layer images' black opaque.
  - `#DEFEXRANK` now applies in BMS output too, the first stage's to the chart and a later stage's from its switch.
  - A stage's `#EXRANKxx` changes (channel `A0`), 97 / 98 volume changes and `#SCROLL` / `#SPEED` changes are kept within its window; the rank changes come as the new `bms-exrank-change` stage-rank table, which only the `lr2` ruleset applies, and a later stage starts at full volume and a scroll of 1.
  - Each stage's mines explode with its own `#WAV00` (`NonstopStitchMap.landmineSampleKeys`, passed to the new `landmineSampleKeys` player option); before, no mine sounded.
  - A negative-BPM reversal inside its stage's window now freezes the rest of the play as LR2 does, instead of the notes, BGM and STOPs past it being played and judged as ordinary ones.
  - Replays keep their recorded rule version, so earlier runs stitch as they did.
  - `stitchNonstopCourse` now also gives each stage's `#BACKBMP` (`NonstopStitchStage.backBMP`, through `assetPath`) and sets the stitched chart's `#BACKBMP` to the first stage's.
- Add `hasRandomMixFirstStage` to `@be-music/player-engine/course`, which tells whether any chart of a RANDOM MIX pool can be stage 1 under the draw settings (the BPM range and limits), reading BPMs only until it finds one. Add `RandomMixConditions.allowBPMChanges` (default `true`) and `RandomMixStageOptions.allowBPMChanges`: a chart whose BPM changes can be stage 1, and the BPM limits and range read its max BPM.
- Fix a NONSTOP course of four or five BMS stages that failed to stitch (`id-space`) when its keysounds or BGA keys together went past the 3843 keys BMS output holds; a 7-key chart commonly uses 800-1,300 keysounds, so four or five of them often did. From stitching rule version 3, `stitchNonstopCourse` stitches such a course as bmson instead, as it already does for a course with CN / HCN long notes. A course that stitched before stitches as it did, and earlier rule versions still refuse it, so existing replays are unchanged. `RandomMixConditions` now takes one `keyMode` in place of the `keyModes` set: LR2 draws a RANDOM MIX in one key mode, and a course plays in one lane layout. `normalizeRandomMixConditions` reads a stored `keyModes` set as one key mode (7 keys when the set holds them, else its lowest).
- A NONSTOP RANDOM MIX now takes 1-99 stages, as an EXPERT one does, instead of at most five; it still has no endless count, which `resolveRandomMixCount` reads as five stages. `RANDOM_MIX_NONSTOP_MAX_COUNT` is removed, and `isRandomMixKept` now keeps any counted draw, however long. `createRandomMixCourse` gives a NONSTOP draw the default connection after every stage, past the five LR2's course maker sets and the ten an LR2 course hash holds. `parseLR2CourseFile` and `serializeLR2CourseFile` take `options.maxStages`: reading defaults to the five stages LR2 plays and reads every stage with `Infinity`; writing defaults to every stage and writes only the first `maxStages` when given. `withNonstopConnection` keeps a long course's connections past the ten the hash holds.
- Add `classifyPlannedAssists` and `resolvePlannedRecordPolicy` to `@be-music/player-engine/records`: the record consequence of the options a play is about to start with, through the classifier and resolver a finished play's record goes through, with chart-dependent findings reported as conditional.
- Add `resolveReplayGaugeHistories` to `@be-music/player-engine/replay`: a replay's gauge under each gauge of its ruleset, re-simulated one gauge at a time, for a result screen that steps its gauge graph.
- Add the battle selection `SP-TO-DP-CORRECTED`, LR2's SP TO DP without DP FLIP on a DP-TO-SP merge; it resolves to `SP-TO-DP` (`isSPToDPBattleMode` tells both apart from the other modes).
- Award FULL COMBO when beatoraja HAZARD supplies the clear lamp, while keeping the existing failure, assist and combo rules.
- Fix a beatoraja seed putting mines and hidden notes on other lanes than beatoraja does under S-RANDOM, H-RANDOM, S-RANDOM-EX, ALL-SCR, PMS CONVERGE and S_RANDOM_PLAYABLE: a timeline's lanes without a note now go to the lanes past the jack threshold first, as beatoraja places them. DP ALL-SCR also takes the lowest-numbered lane on 1P and the highest on 2P, where a released long note used to change its pick.
- Apply chart BASE-SPEED to playback while keeping player tempo, practice eligibility and replay tempo changes relative to that rate.
- Preserve chart load warnings on prepared charts when applying gameplay options.
- Fix a generic bmson keyboard chart playing a course on the 7K or 5K class gauges: the course now picks the KEYBOARD (24K) set, as a single play of the chart does.
- Preserve charatbeatHDX BGA placement in replays and in NONSTOP stage windows.
- LEGACY NOTE on a chart without charge notes or backspin scratches is no longer classified as an assist, and LN REMOVE that removed long notes is now classified as one: live plays record `play.longNoteModifierChangeCount` for LEGACY NOTE and LN REMOVE, which until now was stored only for the long-note additions. A LEGACY NOTE replay without the count still reads as assisted.
- Reproduce LR2 beta3’s 14 KEY scratch avoidance for S-RANDOM and CONVERGE, including the effect of equal-time object order on the eligible key lanes.
- Fix LR2 two-player BATTLE leaving the 2P player without mines when both players pick the same lane option: LR2 copies the arranged 1P lanes to 2P mines included, so `preparePlaybackChart` takes `twoPlayerMines` to copy them too.
- Fix a mine ending an LR2 course run on a GROOVE or EASY pick: LR2 holds mine damage at 2% for those picks in a course too, and so does the course gauge now.
- NONSTOP stitching writes no `#STOP` for a stage's negative `#STOPxx`: the time LR2 takes back for it is already in the stitched note times.
- Fix LR2 gauges running on a fractional TOTAL: under LR2 rules `#TOTAL` and the default TOTAL are truncated to an integer and a value below 1 takes the default, as LR2 keeps TOTAL in an int, so a GROOVE or EASY result near the 80% border matches LR2.
- Speed up beatoraja S-RANDOM by reusing the unheld lane lists and ordering empty, mine-only and hidden-note destinations once per row while preserving seeded arrangements.
- Fix a single-play chart being recorded as assisted because of the Random 2P option, which arranges nothing on it: a beatoraja or AC lane option on 2P now counts only on a chart with a 2P side, as beatoraja builds its 2P modifier only for two-player modes. LR2's 2P SCATTER and CONVERGE still cap the lamp on any chart, as in LR2.
