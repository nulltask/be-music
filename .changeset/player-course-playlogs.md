Record, re-simulate and rank whole course runs in one play log (`@be-music/player/playlog`):

- A course run is one `be-music-course-playlog` file (`BeMusicCoursePlaylog`) holding each stage's own play log, plus the chart facts of any stage the run never reached. `createCoursePlaylog` assembles it and caches the engine's course result, lamped under the judge ruleset the stages were played on; `simulateCoursePlaylog` re-derives the course result stage by stage from the simulated carry-over (the summed judgments, BP including unjudged notes, the course max combo, the course lamp and the trophy); `extractCourseStage` returns one stage as a standalone single-chart log; `parseCoursePlaylog` / `serializeCoursePlaylog` read and write the file; and `aggregateCourseResult`, `resolveCourseLamp`, `resolveCourseTrophy` and `resolveCoursePlaylogFilename` are exported for hosts. A course whose last played stage was given up with ESC is a failed run whatever its gauge, as LR2 records it.
- A NONSTOP run's log holds the stitched play (`BeMusicCoursePlaylog.nonstop`, `PlaylogNonstopRun`, with the `#RANDOM` / `#SWITCH` draws of each stage's chart in `PlaylogNonstopStage.randomDraws`), which `simulateCoursePlaylog` takes the course result from, while `splitNonstopPlaylog` cuts each reached stage out of it as a self-contained stage log (its notes timed from the stage's own zero, the inputs that played them, and the state it started from), so `extractCourseStage` keeps working. `resolveNonstopNoteStages` and `resolveNonstopPlaylogStages` read the stage layout from the stitched chart, and `play.course.rate` records a stage's FIT stretch.
- `computeCourseFingerprint` keys a course as `bmcourse0:<sha256>`, built like the chart fingerprint: `createCourseFingerprintDocument` returns a canonical, versioned document (`v: 'bmcourse0'`) of the course's kind, its normalized and sorted constraints and its stages' chart fingerprints in order, and the fingerprint hashes its RFC 8785 text. A NONSTOP course also lists its connection at each seam (an unnamed seam reads as `fade`, as the stitcher reads it) and its placement mode, since they decide the stitched chart. The same course from a `.lr2crs`, a beatoraja course file or a table shares one key (docs/fingerprint-spec.md §8). `computeCoursePlaylogFingerprint` and `resolveCourseStageChartFingerprints` read it from a course play log; an unreached stage can carry its `chartFingerprint`, so a failed run is keyed too.
- `checkCoursePlaylogEligibility` is the course counterpart of `checkPlaylogEligibility`: every played stage passes the single-play check as a stage of this course, the stages' assists flag the run, and an ESC abort is accepted on the last played stage only. A NONSTOP run is checked like a single play over the stitched play, must cover every course stage with each stage naming its chart, and returns the stitched play's fingerprints as `nonstop`. A run with a stage at another tempo is refused as `tempo`, and one of a course beatoraja keeps off IR, marked `release: false` (kept as `course.release`) or drawn at random, as `unreleased`.
- `resolveCoursePlayedRuleset` gives the judge ruleset every stage of a course run was judged under (a NONSTOP run's stitched play's), or `undefined` when the stages differ; the Leaderboard ranks a run under it, and a host keeps the run's best record under it.
