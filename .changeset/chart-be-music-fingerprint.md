Add the Be-Music Fingerprint (`bmfp0`, see docs/fingerprint-spec.md; the `0` marks the development version, which may still change between releases), which identifies a chart by what the player plays and sees in the lanes rather than by its bytes: `computeChartFingerprint` identifies a chart file with its `#RANDOM` / `#SWITCH` outcomes kept as decision trees, `computePlayFingerprint` hashes the chart after its branches were chosen to identify one play, and `createChartFingerprintDocument` / `createPlayFingerprintDocument` / `canonicalizeFingerprintDocument` expose the canonical document behind them. Charts that differ only in BGA, BGM, keysounds, metadata, line order, `#WAV` numbering, measure resolution, decimal precision, or BMS against bmson (when every position is exact at the bmson resolution) share a fingerprint, while anything the engine plays differently changes it. The fingerprint reads its notes, long notes, mines, BPM / STOP / `#STP` / SCROLL / SPEED and judge-rank / TOTAL facts through the same resolvers as `resolveChart`, so it follows the Resolved layer exactly (one judged note per lane and position, the last BMS `#STOP` at a position, SPEED ramping from 1 before its first keyframe, bmson `total` 100 % read like a chart without `#TOTAL`), and adds only exact positions and snapping: positions and long-note ends are exact, and only decimal values snap to small-denominator rationals within a stable tolerance. Control flow is enumerated with the frame operations of `evaluateControlFlow`, so definitions made in a branch apply to the whole chart in file order, a missing `#ENDIF` behaves as in the parser, and `#ELSE` / `#SWITCH` writings that play alike share a fingerprint; a factor over the evaluation budget gets a deterministic opaque node instead of hanging. The lane mode is read exactly as `resolveChartPlayVariant` reads it, from the lanes, `#PLAYER 3`, the bmson keyboard `mode_hint` and the chart path or extension (`.pms`), which is a required option; the 24 / 48 KEY wheel lanes are ordinary lanes. Both fingerprint functions return the `bmfp0:` string synchronously, hashing with a small built-in SHA-256 instead of Web Crypto, so synchronous callers can use them in Node and browsers alike.

The pieces behind it are exported for other keys and for verifiers: `computeFingerprintOfDocument` hashes a fingerprint document built elsewhere (for example one a client sent to a server) into the same `bmfp0:` string, so a verifier can check a claimed fingerprint against its document without the chart file; `sha256Hex` is the synchronous, dependency-free SHA-256 the fingerprints are hashed with; and `canonicalizeJsonValue` is the RFC 8785 (JSON Canonicalization Scheme) serializer they hash, which the course fingerprint of `@be-music/player/playlog` uses too.
